# 0002 — 不重构目标仓库的测试架构

- 日期：2026-11-01
- 状态：已接受
- 范围：v0.1（首次应用于 OneFLOW）

## 决策

agent-lab **不要求** worker 重构现有测试构建。OneFLOW 审计曾提议新增共享的
`oneflow_case_runtime` CMake 目标，以便测试链接 `TeardownCase`。该提议在 v0.1 中
**被拒绝**。

目标仓库保留现有测试架构：

- `tests/`：CTest/GoogleTest 目标，每个目标列出所需的生产源；
- `test/`：`test.py` 端到端数值回归；
- Python 工具测试；
- `ci/kunshan/*` 硬件/MPI runner。

## 理由

1. 这是对大型、持续开发仓库的构建架构修改，本身没有可测量的性能或正确性收益。
2. 风险高：`MPI`/`METIS`/`CGNS`/`HIP` 等编译定义必须一致传播，否则同一翻译单元在
   测试和生产中会产生不同结果。
3. agent-lab 的职责是协调范围。大范围构建重构属于人工所有的工作。
4. 已知的覆盖缺口可以作为记录结果保留，不应成为重构他人构建系统的理由。

## 后果

- `TeardownCase` 仍未覆盖，作为已知缺口记录，不由 agent-lab 修复。
- 审计提出的契约测试不以此形式加入。
- 如果人工认为该缺口值得处理，应作为独立的人工任务，拥有自己的设计和度量。

## agent-lab 仍可执行的操作

- 按现有模式新增测试：一个测试目标列出所需生产源。
- 修复现有目标能够覆盖的行为缺陷。
- 在报告和 RFC 中记录缺口，供人工决定优先级。
