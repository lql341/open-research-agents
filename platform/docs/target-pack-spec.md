# Target Pack Specification

A **domain pack** is reusable across repositories. A **target pack** is one
concrete repository. `agentlab install <domain> <target> <repo>` copies both into
`<repo>/.agentlab/`; the target overlay wins where the two overlap.

The platform must not contain repository-specific paths, branch names, build
commands, or test commands. Those belong in a target pack.

---

## Layout

```text
targets/<target>/
  target.env            required: identity, base branch, mode, workstreams, commands
  AGENTS.target.md      required: repository-specific rules
  TASKS.md              required: human-owned task board
  scope/<ws>.txt        required: write boundary per workstream
  verification/         required: run_all.sh with 0/1/2 exit contract
  contracts/            optional: repository-specific interfaces/data layout
  repro_fields.yaml     optional: repository-specific evidence fields
  README.md             recommended: how to install and what is special here
```

`install_target.sh` copies the target first, then the domain, then the platform
templates. Files that already exist are never overwritten. `.agentlab/.pack`
records the domain and target so `agentlab update` can re-apply them.

---

## `target.env`

The file is sourced by the platform scripts. Keep it to `KEY=value` lines and
comments.

| Key | Required | Meaning |
|---|---|---|
| `TARGET` | yes | Short name used in worker prompts and status output |
| `BASE_REF` | yes | Git ref workers branch from, e.g. `main`, `dev`, `upstream/hexin` |
| `AGENTLAB_MODE` | yes | `audit` or `worker` |
| `MODULES` | yes | Workstream names, space-separated |
| `BUILD_CMD` | worker | Configure + build command |
| `UNIT_CMD` | worker | Unit/contract test command |
| `VERIFY_CMD` | worker | Numerical/regression gate; must exit `0/1/2` |
| `REQUIRE_CORE` | no | `1` (default) checks a `core/`-style foundation exists |
| `REQUIRE_CONTRACTS` | no | `1` (default) rejects `TODO` / `[CONFIRM]` in contracts |
| `REQUIRE_UNIT` | no | `1` (default) requires a C++ unit test source |
| `UNIT_DIR` | no | Directory checked by `REQUIRE_UNIT` (default `tests/unit`) |
| `BUILD_FILE` | no | Build entry file (default `CMakeLists.txt`) |

Other keys are allowed; the platform ignores unknown keys. Target-specific
variables can be consumed by the target's own verification scripts.

Example:

```sh
TARGET=oneflow
BASE_REF=dev
AGENTLAB_MODE=audit
MODULES="runtime-io numerics"

BUILD_CMD="cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j2"
UNIT_CMD="ctest --test-dir build --output-on-failure"
VERIFY_CMD="bash .agentlab/verification/run_all.sh"

REQUIRE_CORE=0
UNIT_DIR=tests
```

## `AGENTS.target.md`

Repository-specific rules that the generic platform and domain rules cannot know:

- which branch is the base and which branches are protected;
- which directories are human-owned;
- repository-specific evidence rules;
- what a worker must read before changing code;
- what is forbidden in this repository.

`install_target.sh` appends this file to `.agentlab/AGENTS.md` under a
`# --- target: <name> ---` marker. Do not duplicate the generic platform rules.

---

## `scope/<workstream>.txt`

One path prefix or glob per line. Comments start with `#`.

```text
codes/main/src/SomeFile.cpp
tests/main/some_test.cpp
.agentlab/reports/<ws>.md
.agentlab/RFC/<ws>-*
.agentlab/repro/<ws>-*
```

Rules:

- Keep it as narrow as the task allows. Whole directories are usually too broad.
- The scope file is read from `BASE_REF`, so it must be committed before a worker
  starts.
- Untracked `.agentlab/repro/*` files are generated by the gate and ignored by
  `scope_check`; committed repro files are checked like any other path.

---

## `verification/run_all.sh`

A real gate, not a formality.

```text
exit 0  PASS
exit 1  FAIL
exit 2  UNVERIFIED (not built, not registered, or not implemented yet)
```

`worker` gates may report `UNVERIFIED`; `integration` refuses it. A target with a
placeholder verification therefore cannot complete an integration.

Use the repository's existing cases and baselines. Do not create a second
numerical reference set only to make the gate pass.

---

## `TASKS.md`

Human-owned. Workers read the first `todo` for their workstream. A task needs:

- one concrete deliverable;
- exact scope paths;
- observable acceptance criteria;
- what must not change.

Do not put free-form exploration requests here. Use native Pi for exploration.

---

## Installation and updates

```bash
agentlab install <domain> <target> <repo>
agentlab update                 # re-apply the recorded pack, add only new files
agentlab uninstall              # remove .agentlab from the repository
```

`update` never overwrites an existing `.agentlab/` file. If the generated
`.agentlab/AGENTS.md` would change, it writes `AGENTS.md.new` and prints a diff
instead of overwriting a human-edited file.

---

## Adding a new target

1. Copy `targets/oneflow/` as a starting point.
2. Set `TARGET`, `BASE_REF`, `MODULES`, and the commands in `target.env`.
3. Rewrite `AGENTS.target.md`, `TASKS.md`, and `scope/*.txt` for the repository.
4. Add or replace `contracts/` and `verification/`.
5. Install into a scratch clone first, run `agentlab preflight`, and only then
   install into the real repository.

If adding a target requires changing `platform/`, that is a platform change.
Record it as a decision; do not hide repository-specific logic in generic
scripts.
